# Modern Tooling

OSCP teaches things the manual way, deliberately, understanding *how* a technique works matters more than any specific tool. This hub doc is the complementary layer: once a manual technique is actually understood, here's a faster tool for the same job in real practice.

**The line drawn here (confirmed 2026-08-06):** these are speed/quality-of-life upgrades over a manual technique, not exploitation-automation frameworks. Nothing here is sqlmap, Metasploit, or in that same category (find-the-vuln-and-exploit-it-for-you). Every entry either speeds up recon/enumeration, generates a payload artifact faster, or moves data/traffic faster, the actual exploitation decision and technique stays exactly as manual as the module teaches it.

One file per tool, same pattern as [[COMMAND APPENDIX]] and [[COMMAND BREAKDOWNS]]. Each entry names which module section(s) it speeds up, and is explicit about what it does and doesn't replace.

## Tools

- [[TheHarvester]] — passive OSINT aggregator, pulls emails/subdomains/IPs from many public sources in one pass instead of checking WHOIS/Google/Netcraft/GitHub/Shodan by hand
- [[Rustscan]] — full-port-range scanning in seconds instead of minutes, still hands off to `nmap` for the actual service detection
- [[NetExec]] — SMB/AD enumeration and auth spraying across one host or a whole subnet, successor to CrackMapExec
- [[Smtp-user-enum]] — scripted `VRFY`/`EXPN`/`RCPT TO` username enumeration instead of one-at-a-time manual `telnet`
- [[Braa]] — mass SNMP scanning across many hosts at once instead of one `snmpwalk` per host
- [[Feroxbuster]] — recursive content discovery, automatically dives into subdirectories `gobuster` would need a manual re-run for
- [[Ffuf]] — general-purpose fast fuzzer, any injection point (path, header, POST body), not just directory names
- [[Kiterunner]] — API-route-aware brute forcer, tries realistic API paths and correct HTTP methods instead of generic web wordlists
- [[Httpx]] — fast HTTP fingerprinting (status/title/tech-stack) across a whole target list at once
- [[MacroPack]] — generates and obfuscates Office macro payloads, the artifact-building half of [[Client-Side Attacks#12.2.3. Leveraging Microsoft Word Macros|12.2.3]], faster once the manual VBA/chunking process is understood
- [[Ntlm_theft]] — generates a whole batch of NTLM-capturing lure file types at once (including the `.library-ms` format built by hand in [[Client-Side Attacks#Step 2: Build the Windows library file's XML|12.3.1]])
- [[Chisel]] — fast HTTP-tunneled pivoting; same goal as SSH dynamic/remote-dynamic forwarding from [[Port Redirection and SSH Tunneling|Module 19]] but tunnels over HTTP (bypasses firewalls that inspect or block raw SSH), no SSH server on Kali required; supports both reverse variant (Kali as server) and forward variant (pivot as server, Kali connects in)
- [[Ligolo-ng]] — TUN-interface-based pivoting, no `proxychains` needed once a route's added; same transparent-routing goal as `sshuttle` from [[Port Redirection and SSH Tunneling#19.3.5 Using sshuttle|19.3.5]] but without requiring root or Python3 on the server and handles UDP as well as TCP
- [[Rpivot]] — HTTP-tunneled SOCKS4 proxy written in Python; server.py on Kali (port 9999 control + port 9050 SOCKS), client.py on pivot (Python 2.7 required); use when HTTP outbound is the only egress and Go binaries (Chisel) aren't an option
- [[Dnscat2]] — DNS-tunneled C2; wraps commands and shell output inside DNS queries (port 53 UDP); server is a Ruby script on Kali, client is a PowerShell module on the Windows target; very slow, last resort for DNS-only egress environments
- [[Ptunnel-ng]] — ICMP-tunneled TCP; wraps TCP sessions (e.g. SSH) inside ICMP echo packets; requires root on both sides and a static binary (built with LDFLAGS=-static patch to autogen.sh); use when only ICMP ping traffic is allowed outbound
- [[SocksOverRDP]] — Windows-only SOCKS proxy over an RDP virtual channel; a plugin DLL injected into mstsc.exe opens a local SOCKS listener on Kali; server EXE runs on the Windows pivot; Proxifier routes further connections on the pivot through the channel; use when only RDP is accessible and no other tunnel is possible
- [[SysReptor]] — speeds up the notes-to-report handoff specifically (one-click Markdown → PDF, OffSec-sanctioned report templates), not the note-taking itself
- [[SigmaPotato]] — modern SeImpersonatePrivilege escalation, no CLSID required; replaces JuicyPotato for Windows 10/11/2019/2022 targets; [[Windows Privilege Escalation#3. Abusing Windows Privileges (SeImpersonatePrivilege)|17.3.2]]
- [[Evil-WinRM]] — full-featured WinRM shell with built-in upload/download and script pre-loading; speeds up every Module 17 lab that requires a remote Windows shell and file delivery
- [[LinPEAS]] — automated Linux privesc enumeration, colour-coded by severity; replaces the manual checklist from [[Linux Privilege Escalation#18.1.2 Manual Enumeration|18.1.2]] for broad sweeps, though manual work still catches context-dependent misconfigs automated tools miss
- [[Kerbrute]] — Kerberos-based AD username enumeration and password spraying; `userenum` mode has NO lockout risk (pre-auth requests, not full auth); much faster than SMB-based spraying and works without a foothold on the domain
- [[Username-anarchy]] — generates realistic username format candidates (john.smith, jsmith, j.smith, etc.) from a list of real names; output feeds directly into kerbrute userenum
- [[Pypykatz]] — parses LSASS minidump files on Kali with no Windows needed; the offline alternative when Mimikatz is AV-blocked on the target
- [[LaZagne]] — automated multi-app credential extractor for Windows (browsers, databases, mail clients, Windows Credential Manager, DPAPI secrets); run as the compromised user (not SYSTEM) for browser credential access
- [[Snaffler]] — domain-aware SMB share crawler that finds and prioritises credentials and sensitive data across all accessible domain shares; runs from a domain-joined Windows host
- [[Pywhisker-PKINITtools]] — Pass-the-Certificate (PtC) attack chain: pywhisker adds a shadow credential to an AD object (needs GenericWrite), gettgtpkinit.py (PKINITtools) exchanges the cert for a TGT via PKINIT, then use evil-winrm/smbclient -k with no password required
- [[Dislocker]] — decrypts BitLocker-encrypted volumes on Linux via FUSE; three-step chain with losetup (expose VHD as loop device with partitions) + dislocker (decrypt to virtual block device) + mount (NTFS mount)
- [[Inveigh]] — Windows-native LLMNR/NBT-NS poisoning; the PowerShell equivalent of Responder for when you have a Windows foothold but Kali isn't on the segment; captures NTLMv2 challenge-responses from the local network, cracks with hashcat -m 5600; [[Active Directory Enumeration & Attacks (HTB Supplementary)#AD.3. LLMNR/NBT-NS Poisoning from Windows — Inveigh|AD.3]]
- [[DomainPasswordSpray]] — Windows-side password spraying that auto-queries the domain user list from AD (no separate user list needed) and respects the lockout threshold between rounds; use when you have a Windows foothold but no Kali spray path; [[Active Directory Enumeration & Attacks (HTB Supplementary)#AD.5. Password Spraying from Windows — DomainPasswordSpray|AD.5]]
- [[NoPac]] — chains CVE-2021-42278 and CVE-2021-42287 to let any low-privilege domain user impersonate a DC and obtain SYSTEM/DA; uses MachineAccountQuota to create and rename a machine account; scanner.py confirms vulnerability, noPac.py gets the shell; patched November 2021; [[Active Directory Enumeration & Attacks (HTB Supplementary)#AD.13. Bleeding Edge: NoPac (CVE-2021-42278 + CVE-2021-42287)|AD.13]]
- [[BloodHound-Python]] — remote BloodHound data collection from Kali using only valid domain credentials; no binary on the target, queries LDAP; produces the same JSON files as SharpHound; use when AV blocks SharpHound or no Windows foothold yet; [[Active Directory Enumeration & Attacks (HTB Supplementary)#AD.7.1. bloodhound-python — Remote Collection from Kali|AD.7.1]]

- [[Apache NiFi]] — target technology reference, not a speed-up tool; documents how to identify unauthenticated NiFi REST API instances and exploit them via `ExecuteProcess` processor RCE (MSF module `multi/http/apache_nifi_processor_rce`), including the `cmd` arch payload constraint, `SSL false` gotcha, DELAY tuning, and manual Meterpreter upgrade path from a plain PS session; [[The Metasploit Framework#21.4 Capstone|Module 21 Capstone]]

*(More tools get added here as later modules introduce new manual techniques worth speeding up.)*

## Modules with no addition, and why

- **[[SQL Injection Attacks]]**: the obvious speed-up (sqlmap) is already core curriculum in [[SQL Injection Attacks#10.3.2. Automating the Attack|10.3.2]], it's not something to "add," it's already taught as its own topic. No non-automation alternative exists that meaningfully speeds up manual SQLi beyond what's already covered.
- **[[Phishing Basics]]**: already has its own properly-scoped [[Phishing Basics#🎯 Related Tools to Practice|Related Tools to Practice]] section (GoPhish, Evilginx2, King Phisher). Deliberately not duplicated here, and deliberately not expanded, those three are full-campaign automation platforms, the same category this hub doc is explicitly excluding elsewhere (same spirit as sqlmap/Metasploit, just for phishing instead of exploitation).
- **[[Vulnerability Scanning]]**: Nessus is the module's own topic, nothing to speed it up with that wouldn't just be "a worse Nessus." [[Rustscan]] applies to this module's port-scanning prerequisite though, see that entry.
- **[[Common Web Application Attacks]]**: the obvious speed-up (`commix`) automates command-injection discovery *and* exploitation end to end, the same excluded category as sqlmap. The module already carries this exact reasoning inline at the end of [[Common Web Application Attacks#9.4.1. OS Command Injection|9.4.1]], recorded here too so this index stays a complete list rather than requiring a reader to already know which modules were checked.
- **[[Locating Public Exploits]]**: the module's own core teaching *is* the efficient-lookup layer already (`searchsploit`, Exploit-DB, NSE), nothing to speed up further without crossing into the excluded automated vulnerability-to-exploit-matcher category (`nuclei` templates and similar). The module carries this reasoning inline at the end of [[Locating Public Exploits#13.5. Wrapping Up|13.5]].
- **[[Fixing Exploits]]**: `mingw-w64`, `wine`, and `msfvenom`'s bad-char/encoder workflow already are the efficient, manual-but-fast method the module teaches, and Metasploit modules exist for some of the exact CVEs covered here (Sync Breeze, Easy Chat Server), but reaching for those instead would cross into the same excluded find-and-exploit-automatically category as sqlmap/Metasploit generally, the whole point of this module is the adaptation skill itself, not a faster way to skip it. [[Feroxbuster]] applies to this module's own recon step though (see that entry).
- **[[Antivirus Evasion]]**: Shellter and Veil are themselves the efficient tools the module uses -- Shellter for PE injection (there's no non-automated wrapper that speeds it up further without just being "run Shellter for you"), Veil for `.bat`/payload generation (already curriculum, taught as the fast tool even if Wine issues forced a manual bypass in practice). PowerShell IEX itself is already the modern, fast in-memory technique -- the manual `.bat` approach and the IEX download cradle are the fastest non-framework methods available, and there's nothing to speed them up that doesn't cross into full-automation territory (tools like `Invoke-Obfuscation` for PowerShell obfuscation or `Donut` for in-memory PE shellcode are real but map to later, more advanced evasion topics beyond this module's scope).
- **[[Windows Privilege Escalation]]**: winPEAS and PowerUp are already the module's own automated enumeration curriculum (17.1.5) -- they ARE the fast tools, there's no wrapper that speeds them up further. Seatbelt is also curriculum. SigmaPotato (for SeImpersonatePrivilege) and evil-winrm (for WinRM shell delivery) DO get Modern Tooling entries because they're concrete speed-ups over the more manual alternatives (JuicyPotato with its CLSID lookup, and raw `winrs`/`Enter-PSSession` without file transfer). Kernel exploit PoCs (CVE-2023-28252, CVE-2023-29360) are one-shot tools specific to a CVE, not general-purpose speed-ups, so they stay in the module note only.
- **[[Linux Privilege Escalation]]** (partial): unix-privesc-check and LinEnum are already module curriculum (18.1.3) so no separate entry needed for those. LinPEAS DOES get a Modern Tooling entry because it's not module curriculum but is significantly better than LinEnum for real work (actively maintained, colour-coded output, far broader checks). GTFOBins is a reference resource, not a tool. Kernel exploit PoCs (CVE-2017-16995, CVE-2021-4034) are CVE-specific, stay in the module note only.
- **[[Active Directory Introduction and Enumeration]]** (Module 22): PowerView (Get-NetUser/Get-NetGroup/Get-NetComputer/Find-LocalAdminAccess/Get-ObjectAcl/Find-DomainShare) and SharpHound/BloodHound ARE the efficient tools the module teaches — they're already the fast path. The manual .NET LDAPSearch function is the conceptual foundation, not a tool to be sped up. `gpp-decrypt` and `PsLoggedOn` are simple single-purpose utilities with no meaningful wrapper. net.exe is a Windows built-in. Nothing from Module 22 needs a Modern Tooling entry: PowerView is already covered under the HTB Supplementary entry above; BloodHound-Python covers the remote collection scenario; NetExec covers SMB-based enumeration. No new tools or speed-ups introduced.
- **[[Active Directory Enumeration & Attacks (HTB Supplementary)]]** (partial): the core manual techniques (PowerView, Rubeus, mimikatz, BloodHound) ARE the efficient tools the module teaches — they're not things to speed up with a wrapper. The four genuinely new tools that extend the module's capabilities into new scenarios DO get Modern Tooling entries: [[Inveigh]] (Windows-side LLMNR poisoning when Kali isn't on the segment), [[DomainPasswordSpray]] (Windows-side spray when Kali spray paths are blocked), [[NoPac]] (CVE chain, a one-shot exploit rather than a technique wrapper), and [[BloodHound-Python]] (remote collection when SharpHound is AV-blocked). Techniques like GetUserSPNs.py, secretsdump, kerbrute, and crackmapexec are already covered under [[Password Attacks (HTB Supplementary)]] and [[Active Directory Methodology]] and don't need separate entries.
- **[[Attacking Active Directory Authentication]]** (Module 23): Rubeus (asreproast/kerberoast), impacket-GetNPUsers/GetUserSPNs, Mimikatz (kerberos::golden/lsadump::dcsync/sekurlsa::pth), and crackmapexec ARE the efficient tools the module teaches — they're already the fast path for each technique. Spray-Passwords.ps1 is module curriculum (deliberate LDAP sprayer to contrast with CME noise level — no speedup needed). kerbrute is already in Modern Tooling. Nothing new from Module 23 needs an entry here.

- **[[Lateral Movement in Active Directory]]** (Module 24): impacket-wmiexec/psexec/smbexec (-hashes PtH), Mimikatz (sekurlsa::pth/sekurlsa::tickets/kerberos::ptt/kerberos::golden/misc::cmd), PsExec (Sysinternals), crackmapexec (credential spray + Pwn3d! check), and vshadow + impacket-secretsdump are ALL already covered by their own existing entries or are curriculum-taught utilities with no speedup. winrs and New-CimSession are built-in Windows capabilities — no tool wrapper exists or is needed. DCOM lateral movement via MMC20.Application is a living-off-the-land technique by design. Nothing new from Module 24 needs an entry here.
- **[[Port Redirection and SSH Tunneling]]**: `socat`, `ssh` (local/dynamic/remote/remote-dynamic), `sshuttle`, `plink`, and `netsh` ARE the efficient tools the module teaches -- they're not things to be sped up with a wrapper. Chisel, Ligolo-ng, Rpivot, Dnscat2, Ptunnel-ng, and SocksOverRDP DO get Modern Tooling entries (see above) because they extend the module's techniques into scenarios the module doesn't cover: HTTP tunneling when SSH is blocked (Chisel, Rpivot); no-root/no-Python TUN routing (Ligolo-ng); DNS-only environments (Dnscat2); ICMP-only environments (Ptunnel-ng); RDP-only Windows pivots (SocksOverRDP). The HTB "Pivoting, Tunneling, and Port Forwarding" supplementary module [[Pivoting, Tunneling, and Port Forwarding (HTB Supplementary)]] covers all six of these in detail; that's the cross-link for context.
- **[[The Metasploit Framework]]**: Metasploit itself is the exact category this hub doc explicitly excludes (find-the-vuln-and-exploit-it-for-you framework). No speed-up tool entry for MSF as a whole. The Apache NiFi target technology reference (above) is the only addition from this module, and it's scoped to one specific exploitation technique against a specific technology, not MSF generally.
